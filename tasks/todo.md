- `vitest:meeting` = `npx pnpm@10 exec vitest run src/main/meeting`

### T4. Tier 1: процессы из `/proc`

**Описание.** `linuxProcessSnapshot.ts`: перебор числовых каталогов `/proc`, имя из `readlink exe`, запасной путь через `comm`. Чистая часть принимает функции чтения, чтобы тестировать без настоящего `/proc`. Ветка `linux` в `processSnapshot.listProcessNames()`.

**Критерии приемки:**
- [ ] Обычный процесс дает basename в нижнем регистре; суффикс ` (deleted)` срезается
- [ ] Нет прав на `exe` → берется `comm`; процесс исчез во время обхода → пропускается без исключения
- [ ] Любая ошибка обхода → `[]` и `console.warn('[meeting] ...')`; ветка `win32` не изменена

**Проверка:**
- [ ] `vitest:meeting` зеленый (новые тесты на три случая из спецификации плюс `(deleted)`)
- [ ] Ручная: `node -e` с импортом через `vite-node` или временный лог показывает в списке `telegram`/`express`, время обхода записано (ожидаемо единицы миллисекунд на ~700 процессов)

**Зависимости:** T1 (T2 желательно для имен)
**Файлы:** `src/main/meeting/linuxProcessSnapshot.ts`, `src/main/meeting/linuxProcessSnapshot.test.ts`, `src/main/meeting/processSnapshot.ts`
**Объем:** S

### T5. Подключение и звонок в Telegram

**Описание.** Сквозной путь для одной программы. Асинхронный опрос `pw-dump` раз в 2 с с кэшем последнего набора (синхронный вызов подвесит main-процесс, см. план), ветки `linux` в `micConsentStore.ts`, запуск монитора на Linux, Linux-имена Telegram в `patterns.json`.

**Критерии приемки:**
- [ ] `watchMicConsentStore()` на Linux запускает `pw-dump` через асинхронный `execFile` с таймаутом, вызывает `onChange` только при смене набора id, `stop()` останавливает таймер и не дает вызвать колбэк после остановки; второй запуск `pw-dump` не стартует, пока не завершился первый
- [ ] `readMicCaptureEntries()` на Linux отдает кэш наблюдателя, без запуска процессов; без `pw-dump` в системе — `[]`, `null` наблюдателя и одно предупреждение в лог
- [ ] `startMeetingMonitor` работает на `win32` и `linux`; запись `telegram` в `patterns.json` содержит Linux-имена из T2

**Проверка:**
- [ ] `vitest:meeting` зеленый: тесты наблюдателя с подмененным `execFile` и фейковыми таймерами (смена набора, тот же набор, ошибка запуска, `stop`), тест `matchTier1` + `pickAgreedMatch` для `telegram-desktop`
- [ ] `checks` чистые
- [ ] Ручная: сценарии 1, 2, 4, 5 для Telegram с логами `[meeting]` в консоли `pnpm dev`; сценарий 6 — в режиме `off` в логах нет опроса и CPU не растет

**Зависимости:** T3, T4
**Файлы:** `src/main/meeting/linuxMicCapture.ts`, `src/main/meeting/linuxMicCapture.test.ts`, `src/main/meeting/micConsentStore.ts`, `src/main/meeting/meetingMonitor.ts`, `src/main/meeting/patterns.json`
